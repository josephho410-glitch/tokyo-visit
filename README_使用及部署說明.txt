二、主要功能
1. 今日首頁：顯示下一場正式集合、剩餘時間、集合位置、最晚出發時間。
2. 七天行程：新增／修改／刪除行程、狀態管理、交通與休息時間、餐廳候選。
3. 出發設定：每場會議獨立設定最晚出發時間、起點、轉乘方式及備註。
4. 參訪問題：僅東京大學（5 題）與戶田建設（7 題）預載最新《日本參訪說明(1).docx》的完整問句、交流目的，可逐題填寫回答；JAMA、RTRI、NTSEL 不預載問題，只顯示自由筆記。
5. 導航與日文地址卡：重要集合點、飯店與研究機構的日文資料可複製。
6. 自由活動限制提示：最後入場、整理券及開幕時間等注意事項。
7. 待辦清單、私人／公務日圓記帳、CSV 匯出。
8. JSON 備份／還原與自動儲存。
9. 離線閱讀：行程與筆記在網站檔案已成功快取後，可不連網閱讀。
10. 日曆提醒：每場正式集合可匯出 .ics（若已設定出發時間，包含最晚出發項目）。

三、部署到 GitHub Pages
1. 解壓縮 ZIP。解壓後應看到 index.html、data.js、app.js、styles.css、sw.js、manifest.webmanifest、icon-*.png。
2. 建立一個 GitHub repository（如 tokyo-visit）；把上述檔案「全部」上傳到儲存庫根目錄。
3. Repository → Settings → Pages → Build and deployment。
4. Source 選「Deploy from a branch」，Branch 選 main、/(root)，儲存。
5. 等待 GitHub Pages 提供 https://使用者名稱.github.io/tokyo-visit/ 網址。
6. iPhone 使用 Safari 開啟該 HTTPS 網址，分享 → 加入主畫面。
7. 開啟主畫面 App，連網開啟各頁後，切換飛航模式測試行程與筆記。

注意：若用公開的 GitHub Pages 網址，已寫在程式裡的行程、飯店及集合資訊都可被看到。
不要在程式碼中放入護照、訂單編號、私人電話、個資或其他機密資訊。
你在手機 App 中輸入的私有筆記／記帳資料儲存於本機，不會自動同步到 GitHub。
但 iPhone 清除網站資料、更換裝置、主畫面 App 移除，可能造成資料遺失，請經常匯出 JSON。

四、舊版與資料保護
- 若部署到「相同網站網域與使用情境」，能讀取前版 localStorage 時，V2 會保留舊版原始備份，
  並遷入舊版筆記、清單、費用、能辨識的個人自訂行程、提問。
- 舊版預設景點不會強行覆蓋 11/12 最新行程。
- 若舊版部署在不同網域、或 iPhone 主畫面 App 的網站儲存空間彼此獨立，無法自動遷入；
  必須先用舊版匯出 JSON，再從新版「工具」頁匯入。
- 更新程式時，V2 對未修改的預設內容更新，保留已修改的事件、問題、餐廳以及個人新增內容。
- 更新網站前，建議先匯出 JSON 備份。

五、iPhone 背景提醒及離線限制
- 首頁倒數只在 App 正開啟時更新；不保證手機鎖定後背景通知。
- 「匯出日曆提醒」會建立 ICS 檔，須在 iPhone 確認成功匯入行事曆及提醒規則。
- Google Maps、Apple 地圖導航和即時列車班次都需要網路。
- 地圖搜尋字串包含站口，但不保證地圖釘直接對準出口；請核對站內標示。
- 11/18 原行程的筑波快線 07:03–07:58，08:00 集合僅留 2 分鐘；
  強烈建議在前晚查找較早到站的車次。

V2.6 新增：照片附件與離線相簿（2026/11/12）

- 照片存放在 iPhone 這個網站來源的 IndexedDB。無自動雲端同步；GitHub 不會收到私人照片。
- 針對收據以最長邊 2800px 的 JPEG 儲存，其他照片 2000px。這不是原始相機檔案，正式報帳應保留 iPhone「照片」App 中的原始照片。
- 在「工具」頁使用「完整備份（含照片 ZIP）」，請儲存到 iPhone「檔案」App 或 iCloud Drive。舊版 JSON 備份不包含圖片。
- 匯入 V2.6 自行匯出的 ZIP 可還原照片與所有文字紀錄；舊版 JSON 可還原文字紀錄但不包含照片。
- 相片僅在 Safari 裝置本地儲存，移除網頁 App、清除網站資料、系統空間不足等仍可能造成遺失。
- 部署時須多上傳 photos.js；V2.6 應共 10 個檔案，所有檔案放在 GitHub 儲存庫根目錄。
- 重要：iOS 主畫面 PWA 與 Safari 分頁在某些版本或使用方式下可能具有分離的網站儲存空間，請在主要使用的 App 內建立／還原資料。
